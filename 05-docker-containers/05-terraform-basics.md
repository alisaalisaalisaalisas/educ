# 🏗️ Модуль 5.5: Основы Terraform (IaC — Инфраструктура как код)

**Terraform** (от компании HashiCorp) — это главный в мире инструмент для создания и управления инфраструктурой (серверами, сетями, базами данных, DNS) с помощью текстовых конфигурационных файлов.

---

## 🎯 1. Что такое IaC (Инфраструктура как код)?

Раньше системный администратор заходил в панель управления облаком (AWS, Yandex Cloud, Hetzner), тыкал мышкой: *«Создать виртуальную машину ➔ Выбрать 4 CPU ➔ Выбрать 8 GB RAM ➔ Создать диск»*.
* ❌ Это долго, нельзя повторить точь-в-точь, легко ошибиться и невозможно отследить историю изменений.

С **IaC (Infrastructure as Code)** ты описываешь всю нужную инфраструктуру в виде кода на языке **HCL (HashiCorp Configuration Language)**:
```hcl
resource "yandex_compute_instance" "vm_web" {
  name  = "web-server"
  cores = 4
  memory = 8
}
```
* ✅ Ты сохраняешь этот файл в **Git**.
* ✅ Нажимаешь одну команду — и облако само создает 100 одинаковых серверов за 2 минуты!

## 🆚 2. Terraform против Ansible (Любимый вопрос на собеседовании!)

| Критерий | 🏗️ Terraform | 🛠️ Ansible |
| :--- | :--- | :--- |
| **Главная роль** | **Оркестрация / Создание железа** (Infrastructure Provisioning) | **Управление конфигурацией** (Configuration Management) |
| **Что делает** | Создает виртуальные машины, сети, диски, балансировщики и базы данных в облаке. | Заходит внутрь уже созданных серверов: ставит Nginx, настраивает пользователей, раскидывает конфиги. |
| **Подход** | **Декларативный** (*«Я хочу, чтобы в итоге было ровно 3 сервера»*). | Процедурный / Декларативный (шаги выполнения). |
| **Как работают вместе** | **Terraform** создает 3 чистых сервера ➔ передает их IP-адреса в **Ansible** ➔ **Ansible** устанавливает на них софт. |

## 🧩 3. Главные кирпичики Terraform (Синтаксис HCL)

Любой проект на Terraform состоит из 5 базовых блоков:

```
┌────────────────────────────────────────────────────────┐
│ 1. Provider (Провайдер)     ➔ С каким облаком работаем │
│ 2. Resource (Ресурс)        ➔ ЧТО создать (ВМ, диск)   │
│ 3. Variable (Переменные)    ➔ Входные параметры        │
│ 4. Output (Вывод)           ➔ Что вернуть (IP-адрес)   │
│ 5. Data Source (Данные)     ➔ Запросить инфу из облака │
└────────────────────────────────────────────────────────┘
```

### 📄 Пример простого файла `main.tf`:

```hcl
# 1. Провайдер (указываем плагин облака)
terraform {
  required_providers {
    yandex = {
      source = "yandex-cloud/yandex"
    }
  }
}

provider "yandex" {
  zone = "ru-central1-a"
}

# 2. Переменная
variable "instance_name" {
  type    = string
  default = "my-test-server"
}

# 3. Ресурс: создание виртуальной машины
resource "yandex_compute_instance" "vm_app" {
  name = var.instance_name

  resources {
    cores  = 2
    memory = 4
  }

  boot_disk {
    initialize_params {
      image_id = "fd80mrhj8fl2oe878e3e" # Ubuntu 22.04 LTS
      size     = 20
    }
  }

  network_interface {
    subnet_id = "e9b0xxxxxxxxxxxx"
    nat       = true # Выдать публичный белый IP
  }
}

# 4. Output: напечатать полученный IP в терминал после создания
output "server_public_ip" {
  description = "Публичный IP созданного сервера"
  value       = yandex_compute_instance.vm_app.network_interface.0.nat_ip_address
}
```

## 🚀 4. Жизненный цикл Terraform (4 главные команды)

Это «золотой воркфлоу» работы с Terraform:

```
[ Пишем код main.tf ]
         │
         ▼
 1. terraform init     ➔  Скачать плагины провайдеров (AWS, Yandex)
         │
         ▼
 2. terraform plan     ➔  Режим примерки (показать, что изменится: +create, ~modify, -destroy)
         │
         ▼
 3. terraform apply    ➔  РЕАЛЬНО создать ресурсы в облаке
         │
         ▼
 4. terraform destroy  ➔  Удалить ВСЕ созданные ресурсы (чтобы не тратить деньги)
```

### 🧩 Декодер вывода `terraform plan`:
* `+ create` (зеленый плюс) — ресурс будет **создан**.
* `~ update in-place` (желтая тильда) — ресурс будет **изменен** без пересоздания.
* `- destroy` (красный минус) — ресурс будет **удален**.
* `-+/~ replace` — ресурс будет **удален и создан заново** (осторожно, потеря данных!).

## 💾 5. Файл состояния (`terraform.tfstate`) — СВЕРХВАЖНО!

> **`terraform.tfstate` — это база данных Terraform, где записано соответствие между твоим кодом и РЕАЛЬНЫМИ ID ресурсов в облаке.**

### ⚠️ 2 Главных правила безопасности `tfstate`:
1. **НИКОГДА НЕ коммить `terraform.tfstate` в Git!**
   * Внутри `tfstate` пароли от баз данных, приватные ключи и токены хранятся в **ОТКРЫТОМ незашифрованном виде**. Добавь `*.tfstate` в `.gitignore`!
2. **В команде используют Remote Backend (S3 Bucket):**
   * Если над проектом работают 3 инженера, `tfstate` кладут в общее защищенное хранилище (S3 bucket + блокировка DynamoDB/PostgreSQL), чтобы двое коллег не запустили `apply` одновременно и не сломали состояние.

## 💡 Топ-3 вопроса про Terraform на собеседованиях:

1. **Что такое State Drift (Дрифт состояния)?**
   * *Ответ:* Ситуация, когда кто-то руками зашел в веб-консоль облака и поменял настройки (например, увеличил RAM с 4 до 8 ГБ), не изменив код в Terraform. `terraform plan` обнаружит это расхождение и предложит вернуть всё к состоянию в коде.
2. **В чем разница между `terraform plan` и `terraform apply`?**
   * *Ответ:* `plan` — это безопасная симуляция (Dry-run), которая только показывает план действий, но ничего не меняет в облаке. `apply` — реальное применение изменений.
3. **Что делает `terraform refresh`?**
   * *Ответ:* Опрашивает облако и обновляет локальный `tfstate` актуальными данными из реального мира.
