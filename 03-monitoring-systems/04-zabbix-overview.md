# 🏢 Модуль 3.4: Zabbix: Архитектура 7.0 LTS, Agent 2, LLD, Макросы и Эскалации

**Zabbix** — одна из самых зрелых и надежных систем корпоративного мониторинга (Enterprise Monitoring). Она доминирует в банковском секторе, телекоме, дата-центрах и госсекторе благодаря непревзойденной поддержке мониторинга **Bare-Metal серверов, сетевого оборудования (SNMP/IPMI) и виртуализации (VMware/Proxmox)** «из коробки».

## ⚙️ 2. Конфигурация Zabbix Agent 2 (`zabbix_agent2.conf`)

> 💡 **Zabbix Agent 2** написан на **Go**, поддерживает плагинную архитектуру, многопоточный опрос сотен метрик по одному TCP-соединению и встроенные плагины для Docker, PostgreSQL, MySQL, Redis, Systemd.

```ini
# /etc/zabbix/zabbix_agent2.conf

# 1. Пассивный режим: IP адрес Zabbix Server / Proxy, откуда разрешены запросы
Server=192.168.1.50,10.10.0.1

# 2. Активный режим: куда агент сам отправляет метрики
ServerActive=192.168.1.50:10051

# 3. Имя хоста (должно в точности совпадать с именем в веб-интерфейсе Zabbix)
# Либо динамически брать hostname операционной системы:
HostnameItem=system.hostname

# 4. Буфер и таймауты
BufferSize=1000
Timeout=10

# 5. Шифрование сетевого трафика (TLS PSK)
TLSConnect=psk
TLSAccept=psk
TLSPSKIdentity=PSK-PROD-AGENT-01
TLSPSKFile=/etc/zabbix/zabbix_agent_psk.key

# 6. Плагины (например, мониторинг PostgreSQL)
Plugins.PostgreSQL.Sessions.ProdDB.Uri=tcp://127.0.0.1:5432
Plugins.PostgreSQL.Sessions.ProdDB.User=zbx_monitor
Plugins.PostgreSQL.Sessions.ProdDB.Password=SecretPass123!
```

## 🧩 3. Кастомные метрики: `UserParameter` и LLD (Low-Level Discovery)

### 1. `UserParameter` (Простая кастомная метрика)

Позволяет собирать любые параметры через Linux-команды в `/etc/zabbix/zabbix_agent2.d/custom_nginx.conf`:

```ini
# Формат: UserParameter=ключ_метрики[*],команда $1
# Получить активные соединения Nginx:
UserParameter=nginx.active_connections,curl -s http://127.0.0.1/basic_status | awk 'NR==1 {print $3}'

# Метрика с параметром (размер каталога в байтах):
UserParameter=custom.dir.size[*],du -sb "$1" | awk '{print $1}'
```

---

### 2. Скрипты LLD (Low-Level Discovery — Автообнаружение)

LLD позволяет Zabbix автоматически находить сущности (диски, контейнеры, сетевые интерфейсы, базы данных) и создавать для каждой из них `Items` и `Triggers`.

Скрипт должен возвращать JSON со специальными макросами в формате `{#MACRONAME}`:

```json
{
  "data": [
    {
      "{#CONTAINER_ID}": "3a8f9c1b",
      "{#CONTAINER_NAME}": "app_gateway"
    },
    {
      "{#CONTAINER_ID}": "e9b21f4a",
      "{#CONTAINER_NAME}": "postgres_db"
    }
  ]
}
```

Zabbix прочитает этот JSON и автоматически создаст метрики:
`docker.container.cpu[{#CONTAINER_NAME}]` и `docker.container.memory[{#CONTAINER_NAME}]` для каждого найденного контейнера.

## 🎯 4. Макросы и их иерархия (Macros Hierarchy)

Макросы в Zabbix — это переменные конфигурации, заменяющие хардкод (например, пороговые значения нагрузки `{$CPU.UTIL.CRIT}`, логины `{$DB.USER}`, порты `{$NGINX.PORT}`).

### Порядок переопределения макросов (от низшего к высшему приоритету)

```text
1. Глобальные макросы (Administration ➔ General ➔ Macros)
       │ (Переопределяется)
       ▼
2. Макросы Шаблона (Template Macros)
       │ (Переопределяется)
       ▼
3. Макросы Хоста (Host Macros)
       │ (Переопределяется)
       ▼
4. Контекстные макросы Хоста: {$DISK.SPACE.WARN:"/var/log"}
```

> 💡 **Пример контекстного макроса:** На всех дисках порог свободного места 10% (`{$DISK.WARN} = 10`), но для диска бэкапов `/backup` мы задаем контекстный макрос `{$DISK.WARN:"/backup"} = 3`, чтобы алерт не спамил при заполнении до 97%.

## 🪜 5. Действия (Actions) и Многоступенчатые Эскалации

В Zabbix встроен мощный движок эскалаций инцидентов:

```text
[ Триггер перешел в статус PROBLEM: "PostgreSQL Database Down" ]
                             │
                             ▼
  Шаг 1 (0 мин):   Отправить сообщение в Telegram чат дежурной смены (L1).
                             │
            (Проблема не решена за 15 минут)
                             │
                             ▼
  Шаг 2 (15 мин):  Выполнить Remote Command: `systemctl restart postgresql`
                   + Отправить SMS дежурному администратору БД.
                             │
            (Проблема не решена за 30 минут)
                             │
                             ▼
  Шаг 3 (30 мин):  Инициировать голосовой звонок Incident Commander / Тимлиду.
```

## 🆚 6. Сравнение: Prometheus vs Zabbix

| Критерий | 📊 Prometheus + Grafana | 🏢 Zabbix 7.0 LTS |
| :--- | :--- | :--- |
| **Целевая область** | Kubernetes, микросервисы, Cloud Native, Go/Node/Python apps. | Bare-Metal, Hypervisors, VMware, Cisco/Mikrotik Network switches, Enterprise legacy. |
| **Хранилище данных** | Высокооптимизированная TSDB (миллионы метрик в секунду при минимальном CPU/RAM). | Реляционная СУБД (PostgreSQL/MySQL), требует тонкого тюнинга индексов и партиционирования. |
| **Сетевые протоколы** | HTTP `/metrics` (Pull), Pushgateway. | SNMP (v1, v2c, v3), IPMI, JMX, SSH, Telnet, Agent (Active/Passive). |
| **Конфигурация** | GitOps (YAML манифесты, Helm charts, PromQL). | Web UI + Zabbix API (или экспорт YAML шаблонов в Git). |
| **Автоматизация реакции** | Только отправка алертов в каналы связи. | Встроенный запуск удаленных команд на серверах (Remote Scripts), эскалации. |

## 🚫 7. Таблица антипаттернов в Zabbix

| ❌ Антипаттерн | Почему это плохо | ✅ Как делать правильно |
| :--- | :--- | :--- |
| Опрос сотен серверов через пассивный агент (Passive) с одного Zabbix Server | Сервер мониторинга исчерпывает пул `poller processes`, начинаются задержки очередей (Queue delay). | Переводить агенты в **Active Check** или использовать **Zabbix Proxy**. |
| Отсутствие партиционирования таблиц БД (`history`, `trends`) | База данных PostgreSQL вырастает до терабайтов, стандартный `housekeeper` подвешивает диск на 100%. | Использовать **TimescaleDB** или партиционирование таблиц по дням/месяцам. |
| Жесткий хардкод порогов внутри триггеров (`>90`) | Чтобы изменить порог для 100 серверов, придется вручную править каждый триггер. | Использовать макросы шаблонов и хостов `>{$CPU.UTIL.CRIT}`. |
| Использование тяжелых bash-скриптов в `UserParameter` с частотой 1 сек | Высокая нагрузка на процессор наблюдаемого сервера из-за постоянного форка процессов. | Использовать Zabbix Agent 2 с нативными Go-плагинами и интервалом 30–60с. |
