# 🏢 Модуль 3.4: Zabbix: Архитектура, агенты, шаблоны, триггеры

Zabbix — один из самых популярных инструментов корпоративного мониторинга в РФ/СНГ (банки, телеком, ритейл, госсектор).

---

## 1. Архитектура Zabbix

* **Zabbix Server:** Ядро системы. Опрашивает хосты, рассчитывает триггеры, отправляет уведомления, пишет историю в реляционную БД (PostgreSQL / MySQL).
* **Zabbix Database:** Хранит конфигурацию, историю метрик (history) и агрегированные тренды (trends).
* **Zabbix Web UI:** Интерфейс для настройки хостов, графиков, карт сетей и просмотра проблем.
* **Zabbix Agent (1 и 2):** Демон на наблюдаемом сервере.
  * *Пассивный режим (Passive Check):* Сервер сам приходит к агенту на порт `10050` и запрашивает данные.
  * *Активный режим (Active Check):* Агент сам забирает с сервера список метрик и отправляет результат на сервер на порт `10051`.
* **Zabbix Proxy:** Промежуточный сервер для сбора метрик в изолированных филиалах/ДЦ для снижения нагрузки на основной Zabbix Server.

---

## 2. Основные сущности Zabbix

1. **Host (Узел сети):** Наблюдаемый сервер, роутер или сайт.
2. **Item (Элемент данных):** Конкретная метрика (например, `system.cpu.load`, `vfs.fs.size[/,free]`, `net.if.in[eth0]`).
3. **Trigger (Триггер):** Логическое выражение, определяющее проблему (например, `{Host:system.cpu.load.avg(5m)}>5`). Триггер может быть в состоянии `OK` или `PROBLEM`.
4. **Template (Шаблон):** Набор элементов данных, триггеров и графиков, который можно прилинковать к сотням однотипных серверов (например, `Linux by Zabbix agent`).
5. **Action (Действие):** Что делать при переходе триггера в `PROBLEM` (отправить письмо, сообщение в Telegram, запустить скрипт перезапуска службы).
6. **LLD (Low-Level Discovery):** Автоматическое обнаружение дисков, сетевых интерфейсов, баз данных без ручной настройки.

## 3. Сравнение: Prometheus vs Zabbix (Частый вопрос на собеседованиях)

| Критерий | Prometheus + Grafana | Zabbix |
| :--- | :--- | :--- |
| **Целевая среда** | Kubernetes, микросервисы, Cloud Native | Классическая инфраструктура, VM, Bare Metal, сетевое оборудование |
| **Модель данных** | Time Series (числа с метками `key=value`) | Хранение значений в SQL-базе (строки, числа, логи) |
| **Дашборды** | Невероятно гибкие (Grafana) | Встроенные дашборды (проще, но можно подключить Grafana) |
| **Конфигурация** | Как код (GitOps, YAML, Helm) | В основном через Web UI (или Zabbix API) |
| **SNMP / Сетевой мониторинг** | Требуется snmp_exporter | «Из коробки» отличная поддержка SNMP, IPMI, JMX |
