# 🌐 Модуль 2.1: Основы сетей: OSI, TCP/IP, DNS, HTTP/HTTPS

Понимание работы сетей необходимо для локализации сетевых задержек, сбоев маршрутизации, проблем с DNS и ошибок веб-серверов.

---

## 1. Стек TCP/IP и Модель OSI (Практический взгляд)

Инженеру мониторинга не нужно заучивать теоретические детали, важно понимать, на каком уровне произошел сбой:

| Уровень OSI | Протоколы | Что ломается | Инструменты диагностики |
| :--- | :--- | :--- | :--- |
| **7. Прикладной (Application)** | HTTP, HTTPS, DNS, SSH, SMTP | 502/504 ошибки, истек SSL-сертификат, DNS не резолвит | `curl -Iv`, `dig`, `openssl` |
| **4. Транспортный (Transport)** | TCP, UDP | Закрыт/заблокирован порт, сброс соединения (RST), тайм-аут | `telnet`, `nc -zv`, `ss -tulpn` |
| **3. Сетевой (Network)** | IP, ICMP | Нет маршрута к хосту, потери пакетов (Packet Loss) | `ping`, `traceroute`, `mtr` |
| **2. Канальный (Data Link)** | Ethernet, ARP, VLAN | Физические петли, флаппинг интерфейса, ошибки MTU | `ip link`, `ip neigh` |

## 2. Как работает DNS (Domain Name System)

Когда браузер или сервер обращается к `api.example.com`:
1. Проверяется локальный кэш и файл `/etc/hosts`.
2. Запрос отправляется на резолверы из `/etc/resolv.conf` (например, `8.8.8.8` или внутренний DNS).
3. Идет рекурсивный опрос: Корневой DNS (`.`) → Зона `.com` → DNS-серверы `example.com` (NS-записи).
4. Возвращается `A` (IPv4) или `AAAA` (IPv6) запись.

### Основные типы DNS-записей:
* **A / AAAA:** адрес IPv4 / IPv6.
* **CNAME:** каноническое имя (псевдоним/алиас на другой домен).
* **MX:** почтовые серверы.
* **TXT:** текстовые данные (SPF, DKIM, валидация домена).
* **NS:** авторитетные серверы имен.

## 3. Протокол HTTP/HTTPS и Коды Ответов

### Анатомия HTTP-запроса:
* **Методы:** `GET` (чтение), `POST` (создание), `PUT`/`PATCH` (изменение), `DELETE` (удаление), `HEAD` (только заголовки).
* **Заголовки (Headers):** `Host`, `User-Agent`, `Authorization`, `Content-Type`, `X-Forwarded-For`.

### Коды ответов HTTP (Must Know для дежурного):

* **2xx (Успех):**
  * `200 OK` — запрос успешно обработан.
* **3xx (Перенаправление):**
  * `301 Moved Permanently` — постоянный редирект (кэшируется).
  * `302 Found` — временный редирект.
* **4xx (Ошибка клиента):**
  * `400 Bad Request` — кривой синтаксис запроса.
  * `401 Unauthorized` — нет авторизации (требуется логин/токен).
  * `403 Forbidden` — доступ запрещен правами.
  * `404 Not Found` — ресурс не найден.
  * `429 Too Many Requests` — сработал Rate Limit (слишком много запросов).
* **5xx (Ошибка сервера):**
  * `500 Internal Server Error` — упало само бэкенд-приложение (необработанный exception в коде).
  * `502 Bad Gateway` — Nginx (прокси) не смог получить ответ от бэкенда (бэкенд упал или порт закрыт).
  * `503 Service Unavailable` — сервис перегружен или выключен на обслуживание.
  * `504 Gateway Timeout` — бэкенд слишком долго отвечает (завис тяжелый SQL-запрос).

## 4. Стандартные сетевые порты

* `22` — SSH
* `53` — DNS (UDP/TCP)
* `80` — HTTP
* `443` — HTTPS
* `3306` — MySQL / MariaDB
* `5432` — PostgreSQL
* `6379` — Redis
* `9090` — Prometheus
* `3000` — Grafana
* `10050/10051` — Zabbix Agent / Zabbix Server
