# 🌍 Модуль 2.4: CDN (Content Delivery Network) и архитектура с Ingress в Kubernetes

**CDN (Сеть доставки контента)** — это распределенная по всему миру сеть серверов-посредников (Edge-серверов), которая ускоряет загрузку сайтов, кэширует статику и защищает твой кластер от DDoS-атак.

Популярные CDN: **Cloudflare, AWS CloudFront, Fastly, Akamai, Yandex Cloud CDN**.

---

## 🗺️ 1. Полная схема прохождения трафика (От браузера до пода в K8s)

```
[ 👤 Пользователь (в Риме, Токио или Москве) ]
                       │
                       ▼ (DNS Anycast резолвит ближайший к юзеру дата-центр)
┌─────────────────────────────────────────────────────────────┐
│             CDN EDGE СЕРВЕР (например, Cloudflare)          │
│                                                             │
│ 1. Кэш статики: Отдает картинки, видео, JS и CSS мгновенно! │
│ 2. WAF & Anti-DDoS: Фильтрует ботов, SQL-инъекции и атаки  │
│ 3. SSL Termination: Расшифровывает HTTPS на границе         │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               │ (Только динамические API-запросы / Cache Miss)
                               ▼ (HTTPS через защищенный туннель)
┌─────────────────────────────────────────────────────────────┐
│            Внешний Cloud Load Balancer (AWS / YC)           │ (Белый IP кластера)
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼ (Порт 443 / 80)
┌─────────────────────────────────────────────────────────────┐
│          KUBERNETES INGRESS CONTROLLER (Nginx / Envoy)      │
│                                                             │
│ • Восстанавливает реальный IP клиента (CF-Connecting-IP)    │
│ • Маршрутизирует трафик по доменам и путям (/api ➔ backend) │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼ (Внутренняя сеть ClusterIP)
┌─────────────────────────────────────────────────────────────┐
│           KUBERNETES SERVICE ➔ APPLICATION PODS             │
│                 (Твое приложение на Go / Java)              │
└─────────────────────────────────────────────────────────────┘
```

## ⚡ 2. Какую работу берет на себя CDN?

1. **Кэширование статических файлов (Edge Caching):**
   * Если 1 000 000 пользователей запросили `logo.png` или `bundle.js`, этот запрос **НЕ долетит до твоего Kubernetes кластера**! 
   * CDN ответит из своего кэша за 5 миллисекунд (`CF-Cache-Status: HIT`). Нагрузка на твои серверы падает на 70–90%!
2. **Защита от DDoS-атак:**
   * Если сайт атакуют боты с мощностью 500 Гбит/с, емкость CDN (у Cloudflare более 200 Тбит/с) поглощает этот мусор на своих пограничных шлюзах.
3. **GeoDNS (Anycast):**
   * Пользователь из Европы попадает на сервер во Франкфурте, пользователь из Азии — в Сингапуре.

## 🕵️‍♂️ 3. Проблема реального IP-клиента (Must Know в DevOps!)

Когда перед твоим сервером встает CDN, **для твоего Nginx Ingress все входящие запросы приходят с IP-адресов CDN**!

* Если клиент с IP `195.20.10.5` совершит спам, твой Nginx в логах увидит IP прокси Cloudflare (например, `172.68.25.10`).
* Если заблокировать этот IP, ты **заблокируешь миллионы других клиентов**!

### 🛠️ Как это решается:
CDN передает реальный IP пользователя в специальном HTTP-заголовке:
* Cloudflare: **`CF-Connecting-IP`**
* Другие CDN: **`X-Forwarded-For`** или **`True-Client-IP`**

#### Настройка Nginx Ingress в Kubernetes (`values.yaml`):
```yaml
controller:
  config:
    use-forwarded-headers: "true"
    compute-full-forwarded-for: "true"
    # Доверяем IP-диапазонам Cloudflare:
    enable-real-ip: "true"
    real-ip-header: "CF-Connecting-IP"
    set-real-ip-from: "173.245.48.0/20,103.21.244.0/22,104.16.0.0/13"
```
После этого переменная `$remote_addr` в логах Nginx снова показывает **настоящий IP пользователя**!

## 🛡️ 4. Как защитить Ingress от обхода CDN (Origin Shielding)

Злоумышленник может просканировать интернет, найти реальный IP-адрес твоего Ingress-контроллера и атаковать его **напрямую в обход Cloudflare**.

Есть **3 способа защиты бэкенда**:

### 1. Файрвол / Security Group (Самый популярный)
В файрволе облака разрешить входящий трафик на 443 порт **ТОЛЬКО с официальных подсетей IP-адресов CDN** (все остальные подключения из интернета сбрасывать).

### 2. Cloudflare Authenticated Origin Pulls (mTLS)
Nginx Ingress требует SSL-сертификат клиента при подключении. Только серверы Cloudflare имеют этот приватный ключ.

### 3. Cloudflare Tunnel (`cloudflared` в Kubernetes) 🏆
Внутри твоего Kubernetes запускается маленький под `cloudflared`. 
* Твой кластер **вообще не имеет публичного белого IP** и не слушает порты наружу!
* Под сам изнутри кластера открывает исходящий туннель к Cloudflare. Взломать такой кластер снаружи напрямую невозможно.

## 📊 5. Как проверять работу CDN через `curl`

```bash
# Проверяем заголовки ответа:
curl -Iv https://example.com/static/image.png
```

Смотри на заголовки:
* **`cf-cache-status: HIT`** ➔ Файл отдан из кэша CDN за 3 миллисекунды (до твоего сервера запрос даже не дошел).
* **`cf-cache-status: MISS`** ➔ Файла не было в кэше, CDN сходил в твой Ingress/бэкенд, забрал файл и сохранил в кэш.
* **`cf-cache-status: DYNAMIC`** ➔ Это API-запрос (`/api/login`), он не кэшируется и сразу проксируется в кластер.
* **`cf-ray: 8b45c0...`** ➔ Уникальный ID запроса в CDN для траблшутинга.
