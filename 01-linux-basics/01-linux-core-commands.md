# 🐧 Модуль 1.1: Полный детальный разбор всех ключевых команд Linux

Ниже разобран **каждый инструмент** из списка с подробным объяснением: зачем он нужен, какие флаги используются и реальные примеры из практики дежурного инженера.

---

## 📂 Блок 1. Файлы, каталоги и навигация

### 1. `ls` (List) — просмотр содержимого папки
* **Зачем:** увидеть файлы, папки, их владельцев, размер и права.
* **Флаги:**
  * `-l` (long) — подробный список (права, владелец, размер, дата).
  * `-a` (all) — показывать скрытые файлы (начинаются с точки `.`).
  * `-h` (human-readable) — показывать размер в КБ/МБ/ГБ вместо байт.
* **Пример:**
  ```bash
  ls -lah /var/log/
  ```

---

### 2. `cd` (Change Directory) — переход по директориям
* **Зачем:** перемещаться по файловой системе.
* **Примеры:**
  ```bash
  cd /etc/nginx/     # Абсолютный переход в папку
  cd ..              # Подняться на 1 уровень выше
  cd ~               # Перейти в свою домашнюю папку (/home/user)
  cd -               # Вернуться в предыдущую папку, где только что был
  ```

---

### 3. `pwd` (Print Working Directory) — показать текущий путь
* **Зачем:** понять, в какой папке ты находишься прямо сейчас.
* **Пример:**
  ```bash
  pwd
  # Вывод: /var/www/html/api
  ```

---

### 4. `cat` и `less` — чтение файлов
* **`cat`:** вываливает весь файл в терминал целиком (удобно для коротких конфигов).
  ```bash
  cat /etc/resolv.conf
  ```
* **`less`:** открывает файл в удобном режиме постраничного чтения (не вешает терминал при файлах в гигабайты).
  * `Пробел` — листать вниз.
  * `/слово` — поиск слова в файле (нажать `n` для следующего совпадения).
  * `q` — выйти.
  ```bash
  less /var/log/syslog
  ```

---

### 5. `head` и `tail` — начало и конец файла
* **`head -n 20 file`:** вывести первые 20 строк файла.
* **`tail -n 50 file`:** вывести последние 50 строк файла.
* **`tail -f file`:** «живой» режим — терминал не закрывается, а выводит новые строки на лету по мере их записи приложением.
  ```bash
  tail -f /var/log/nginx/error.log
  ```

---

### 6. `find` — глубокий поиск файлов на диске
* **Зачем:** найти файлы по имени, размеру или дате изменения.
* **Флаги:**
  * `-type f` (только файлы), `-type d` (только папки).
  * `-name "*.log"` (маска имени).
  * `-size +50M` (файлы больше 50 МБ).
  * `-mtime +7` (изменены более 7 дней назад).
* **Примеры:**
  ```bash
  # Найти все логи тяжелее 100 МБ
  find /var/log -type f -name "*.log" -size +100M

  # Найти и сразу удалить файлы старше 30 дней
  find /tmp -type f -mtime +30 -exec rm -f {} \;
  ```

---

### 7. `df` и `du` — дисковое пространство
* **`df -h` (Disk Free):** показывает свободное место на всех смонтированных дисках в человеческом формате (`-h`).
* **`df -i`:** показывает свободные **inodes** (индексные дескрипторы).
* **`du -sh /path` (Disk Usage):** показывает, сколько места занимает конкретная папка или файл.
  * `-s` (summary — суммарно).
  * `-h` (human-readable — в МБ/ГБ).
* **Пример:**
  ```bash
  # Узнать топ-5 самых тяжелых папок в /var
  du -sh /var/* 2>/dev/null | sort -hr | head -n 5
  ```

---

## 🔍 Блок 2. Фильтрация и анализ текста (Логи)

### 8. `grep` (Global Regular Expression Print) — поиск по тексту
* **Зачем:** найти нужные строки в логах или коде.
* **Флаги:**
  * `-i` (ignore-case) — не учитывать регистр (найдет и `error`, и `ERROR`).
  * `-r` (recursive) — искать рекурсивно во всех подпапках.
  * `-n` (number) — показать номер строки.
  * `-v` (invert) — показать строки, где НЕТ совпадения (исключение).
* **Примеры:**
  ```bash
  grep -rn "502 Bad Gateway" /var/log/nginx/
  grep -v "DEBUG" app.log
  ```

---

### 9. `awk` — работа с колонками (столбцами)
* **Зачем:** вырезать определенные поля из строки (например, IP-адрес или HTTP-код).
* **Примеры:**
  ```bash
  # Вывести 1-й столбец (по умолчанию разделитель - пробел)
  awk '{print $1}' /var/log/nginx/access.log

  # Вывести имена пользователей из /etc/passwd (разделитель - двоеточие -F:)
  awk -F: '{print $1, $7}' /etc/passwd
  ```

---

### 10. `sort`, `uniq`, `wc` — обработка списков
* **`sort`:** сортировка строк по алфавиту или числам (`-n` числовая, `-r` задом наперед).
* **`uniq -c`:** удаляет дубликаты и считает количество повторов (`-c` count). **Важно:** работает только на отсортированном тексте!
* **`wc -l`:** подсчет количества строк (**l**ines).
* **Пример боевой связки:**
  ```bash
  # Сколько раз встретился каждый IP-адрес в логе (от большего к меньшему):
  awk '{print $1}' access.log | sort | uniq -c | sort -nr | head -n 10
  ```

---

## 📦 Блок 3. Архивация и сжатие файлов

### 11. `tar` (Tape Archive) — упаковка файлов в архив
* **Зачем:** упаковать десятки файлов/папок в один файл (сжатый или несжатый).
* **Флаги:**
  * `-c` (create) — создать архив.
  * `-x` (extract) — распаковать.
  * `-z` (gzip) — сжать алгоритмом gzip.
  * `-v` (verbose) — показывать процесс на экране.
  * `-f` (file) — указать имя архива.
* **Примеры:**
  ```bash
  # Создать архив папки nginx:
  tar -czvf nginx_backup.tar.gz /etc/nginx/

  # Распаковать архив в папку /tmp/restore:
  tar -xzvf nginx_backup.tar.gz -C /tmp/restore/
  ```

---

### 12. `gzip` / `gunzip` и `zip` / `unzip`
* **`gzip file.log`:** сжимает **один файл на месте** (получается `file.log.gz`, оригинал удаляется).
* **`gunzip file.log.gz`:** распаковывает файл обратно.
* **`zip -r archive.zip /folder/`:** создает кроссплатформенный zip-архив.
* **`unzip archive.zip -d /target/`:** распаковывает zip.

---

## 🌐 Блок 4. Сети, удаленный доступ и передача файлов

### 13. `ssh` (Secure Shell) — удаленное управление
* **Зачем:** безопасное подключение к консоли удаленного сервера по порту 22.
* **Примеры:**
  ```bash
  ssh user@192.168.1.50
  ssh -i ~/.ssh/id_rsa -p 2222 deploy@server.com
  ```

---

### 14. `scp` и `rsync` — передача файлов по сети
* **`scp` (Secure Copy):** простое копирование файлов через SSH.
  ```bash
  # Залить файл на сервер:
  scp config.json user@192.168.1.50:/etc/app/

  # Скачать файл с сервера:
  scp user@192.168.1.50:/var/log/syslog ./server_syslog.log
  ```
* **`rsync` (Remote Sync):** профессиональная синхронизация директорий. Передает **только изменившиеся куски файлов**, сжимает трафик и восстанавливается при обрыве связи.
  * Флаги `-avz`: `-a` (архивный режим: сохраняет права и даты), `-v` (подробно), `-z` (сжатие на лету).
  ```bash
  rsync -avz --progress /var/www/ user@192.168.1.50:/var/www/
  ```

---

### 15. `sshfs` — монтирование удаленной папки
* **Зачем:** подключить папку с удаленного сервера так, будто это твоя локальная папка на диске.
* **Пример:**
  ```bash
  sshfs user@192.168.1.50:/var/log /mnt/remote_logs
  # Теперь можно смотреть логи сервера прямо в /mnt/remote_logs!
  # Чтобы отключить:
  umount /mnt/remote_logs
  ```

---

### 16. `ping`, `traceroute`, `mtr` — проверка сетевой связности
* **`ping -c 4 8.8.8.8`:** проверка доступности хоста по протоколу ICMP и замера задержки (RTT).
* **`traceroute 8.8.8.8`:** показывает всю цепочку промежуточных маршрутизаторов (роутеров) от тебя до цели. Помогает понять, на чьей стороне (нашего провайдера или магистрала) теряются пакеты.

---

### 17. `dig` и `nslookup` — DNS-диагностика
* **Зачем:** проверить, в какой IP-адрес резолвится доменное имя.
* **Примеры:**
  ```bash
  dig google.com +short            # Быстро получить только IP
  dig @8.8.8.8 example.com MX      # Спросить конкретный DNS-сервер о почтовых записях
  nslookup ya.ru
  ```

---

### 18. `curl` и `wget` — сетевая загрузка и HTTP-запросы
* **`wget https://site.com/file.tar.gz`:** утилита для скачивания файлов из интернета в фоновом режиме.
* **`curl`:** мощный инструмент отправки любых HTTP/HTTPS запросов (GET, POST, заголовки):
  ```bash
  # Скачать файл:
  curl -O https://site.com/file.tar.gz

  # Посмотреть заголовки и статус-код (без тела ответа):
  curl -Iv https://example.com

  # Проверить ответ конкретного бэкенда напрямую:
  curl -H "Host: api.example.com" http://10.0.0.15:8080/health
  ```

---

### 19. `ip`, `ifconfig`, `ss`, `netstat` — локальный сетевой стек
* **`ip a` (или `ifconfig`):** посмотреть свои сетевые карты и назначенные IP-адреса.
* **`ss -tulpn` (или `netstat -tulpn`):** показывает все порты, которые слушаются программами на этом сервере.
  * `-t` (TCP), `-u` (UDP), `-l` (listening — только слушающие), `-p` (process — имя программы и PID), `-n` (numeric — числа вместо имен).

## 💾 Блок 5. Диски, разделы и файловые системы

### 20. `fdisk` и `parted` — разметка разделов
* **Зачем:** создать или изменить таблицу разделов на новом жестком диске.
* **`fdisk /dev/sdb`:** классическая утилита (для дисков до 2 ТБ, разметка MBR/GPT).
* **`parted /dev/sdb`:** современная утилита для дисков любого объема (GPT).

---

### 21. `mkfs` (Make Filesystem) — форматирование диска
* **Зачем:** создать файловую систему на чистом разделе перед использованием.
* **Примеры:**
  ```bash
  mkfs.ext4 /dev/sdb1    # Создать ФС ext4
  mkfs.xfs /dev/sdb2     # Создать ФС XFS (быстрее для баз данных)
  ```

---

### 22. `mount` и `umount` — монтирование
* **Зачем:** подключить отформатированный раздел диска к определенной папке в файловой системе.
* **Примеры:**
  ```bash
  # Подключить диск к папке /mnt/data:
  mount /dev/sdb1 /mnt/data

  # Отключить диск (перед извлечением):
  umount /mnt/data
  ```

---

## ⚡ Блок 6. Мониторинг ресурсов и отладка процессов

### 23. `free` — оперативная память
* **Зачем:** увидеть, сколько памяти занято, свободно и отдано под кэш ядра.
* **Пример:**
  ```bash
  free -m    # В мегабайтах
  free -h    # В человеческом формате (ГБ)
  ```

---

### 24. `top` и `htop` — мониторинг в реальном времени
* **Зачем:** интерактивный диспетчер задач. Показывает Load Average, использование CPU каждым процессом, потребление RAM.
* В `htop` можно искать процессы по клавише `F3` и отправлять сигналы (`kill`) по `F9`.

---

### 25. `vmstat` (Virtual Memory Statistics)
* **Зачем:** комплексный отчет о процессах, памяти, подкачке (swap), дисковом вводе-выводе и процессоре.
* **Пример:**
  ```bash
  vmstat 2 5   # Выводить статистику каждые 2 секунды, 5 раз
  ```
  * Колонки `si` (swap in) и `so` (swap out) показывают, сбрасывает ли система память на диск (если числа больше 0 — серверу не хватает RAM!).

---

### 26. `iostat` (I/O Statistics)
* **Зачем:** диагностика медленных дисков (утилита пакета `sysstat`).
* **Пример:**
  ```bash
  iostat -xz 1 5
  ```
  * Колонка `%util` — загруженность диска (если близко к 100% — диск захлебывается).
  * `await` — среднее время ожидания ответа от диска в миллисекундах.

---

### 27. `strace` (System Call Tracer) — рентген процессов
* **Зачем:** перехватывает все системные вызовы программы к ядру (когда приложение зависло, падает без логов или работает медленно).
* **Критически важные флаги (Must Know):**
  * `-f` (**f**ork / threads) — **САМЫЙ ВАЖНЫЙ ФЛАГ!** Отслеживать не только главный процесс, но и все его дочерние потоки/воркеры (Java, Nginx, Go, Python). Без `-f` вы часто ничего не увидите.
  * `-o output.txt` — сохранить лог вызовов в файл (терминал не захламится миллионом строк).
  * `-s 2048` (**s**ize) — по умолчанию `strace` обрезает длинные строки до 32 символов. Флаг `-s` позволяет увидеть полные SQL-запросы, пути к файлам и HTTP-тела.
  * `-T` — показывает **время выполнения каждого вызова в секундах** (помогает мгновенно найти вызов, который висел 5 секунд).
  * `-tt` — добавляет точное время с микросекундами к каждой строке.
  * `-p PID` — подключиться к уже запущенному процессу.
  * `-e trace=...` — фильтрация по типу: `file` (файлы), `network` (сеть), `process` (создание процессов), `signal` (сигналы).
  * `-c` (count) — итоговая статистика (сколько раз вызывался каждый syscall и сколько времени занял).

#### 💡 Примеры реального использования:
```bash
# 1. Полноценная отладка зависшего процесса со всеми тредами и замером времени:
strace -f -T -tt -s 1024 -p 12345 -o /tmp/strace_debug.log

# 2. Посмотреть, какие файлы пытается открыть сервис:
strace -e trace=file nginx

# 3. Посмотреть сетевые соединения (к каким IP/портам подключается сервис):
strace -e trace=network -p 12345

# 4. Сводная статистика (почему команда работает медленно):
strace -c ls -la
```

#### 🧩 Как читать коды возврата `strace`:
* `openat(...) = 3` ➔ Успешно! Файлу присвоен дескриптор `3`.
* `= -1 ENOENT (No such file or directory)` ➔ Файл не найден.
* `= -1 EACCES (Permission denied)` ➔ Нет прав на чтение/запись файла.
* `= -1 ETIMEDOUT (Connection timed out)` ➔ Сетевой запрос завис и отвалился по тайм-ауту.
* `= -1 ECONNREFUSED (Connection refused)` ➔ Порт закрыт / сервис не запущен.
* `= -1 EMFILE (Too many open files)` ➔ Процесс уперся в лимит открытых дескрипторов `ulimit -n`.

## 🔒 Блок 7. Права доступа, службы и управление сервером

### 28. `chmod` и `chown` — безопасность файлов
* **`chmod`:** изменение прав доступа (`r`=4 чтение, `w`=2 запись, `x`=1 запуск).
  ```bash
  chmod 755 script.sh    # rwxr-xr-x (владелец: всё, остальные: чтение и запуск)
  chmod 600 id_rsa       # rw------- (только владелец может читать ключ)
  chmod +x test.sh       # сделать исполняемым
  ```
* **`chown`:** изменение владельца и группы.
  ```bash
  chown -R www-data:www-data /var/www/html/
  ```

---

### 29. `systemctl` и `journalctl` — управление службами
```bash
systemctl status nginx       # Проверить статус службы
systemctl restart nginx      # Перезапустить службу
systemctl reload nginx       # Перечитать конфиг без обрыва соединений
systemctl enable nginx       # Включить автозапуск при старте системы

journalctl -u nginx -n 50 --no-pager  # Посмотреть последние 50 строк лога службы
journalctl -u nginx -f                 # Следить за логом службы онлайн
```

---

### 30. `reboot` и `shutdown` — перезагрузка и выключение
```bash
reboot                  # Перезагрузить сервер сейчас
shutdown -h now         # Выключить сервер немедленно
shutdown -r +15 "Техработы через 15 минут"  # Запланировать ребут с уведомлением
```
