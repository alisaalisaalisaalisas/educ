## 🔀 1. Стандартные потоки ввода-вывода и Редиректы

Каждый запущенный процесс в Linux автоматически получает три потока дескрипторов:

| Номер | Имя потока | Что это такое | Куда направлен по умолчанию |
| :--- | :--- | :--- | :--- |
| **0** | `stdin` (Standard Input) | Входящий поток данных | Клавиатура терминала |
| **1** | `stdout` (Standard Output) | Стандартный поток вывода (обычный текст программы) | Экран терминала |
| **2** | `stderr` (Standard Error) | Поток ошибок и аварийных сообщений | Экран терминала |

---

### Операторы перенаправления (Редиректы):

```bash
# 1. Перенаправить stdout в файл (перезаписать файл)
echo "Hello World" > output.txt

# 2. Дописать stdout в конец файла (не затирая старое)
echo "Новая строка лога" >> output.txt

# 3. Перенаправить ТОЛЬКО ошибки (stderr - 2) в отдельный файл
ls /not_existing_folder 2> errors.log

# 4. Заглушить ошибки (отправить в «черную дыру» /dev/null)
find / -name "*.conf" 2>/dev/null

# 5. Перенаправить И обычный вывод, И ошибки в один файл (Золотой стандарт для крона):
/opt/scripts/backup.sh > /var/log/backup.log 2>&1
# Современный короткий аналог в bash:
/opt/scripts/backup.sh &> /var/log/backup.log

# 6. Утилита `tee`: выводить текст одновременно на экран И писать в файл
cat /var/log/nginx/access.log | grep "502" | tee /tmp/502_errors.log
```

## 🌍 2. Переменные окружения (Environment Variables) и `$PATH`

### Что такое переменная `$PATH`?
Когда ты вводишь в терминале `nginx` или `curl`, система не знает заранее, где лежит этот файл. Она последовательно ищет бинарник в папках, перечисленных в переменной `$PATH` через двоеточие:

```bash
$ echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

> ⚠️ **Ошибка «command not found»:** означает, что файла либо нет в системе, либо папки с этим файлом нет в `$PATH`.

### Управление переменными окружения:
```bash
# 1. Посмотреть все переменные текущей сессии
env
# или
printenv

# 2. Создать переменную окружения (экспортировать для дочерних процессов)
export DB_PORT="5432"
export APP_ENV="production"

# 3. Добавить свою папку со скриптами в $PATH:
export PATH=$PATH:/opt/my_scripts

# 4. Сделать переменную постоянной (чтобы не сбрасывалась при закрытии терминала):
# Дописать строку export в конец файла ~/.bashrc (или ~/.zshrc)
echo 'export PATH=$PATH:/opt/my_scripts' >> ~/.bashrc
source ~/.bashrc # Применить изменения не выходя из сессии
```

## 📦 3. Пакетные менеджеры в Linux (`apt` vs `dnf`/`yum`)

В разных дистрибутивах Linux используются разные пакетные менеджеры:

### Семейство Debian / Ubuntu (`apt` / `dpkg`):
```bash
# 1. Обновить локальный кэш списка пакетов из репозиториев
sudo apt update

# 2. Установить пакет
sudo apt install -y nginx curl jq

# 3. Обновить все установленные пакеты до свежих версий
sudo apt upgrade -y

# 4. Удалить пакет (с удалением конфигурационных файлов)
sudo apt purge nginx

# 5. Низкоуровневая утилита dpkg (проверка установленного пакета):
dpkg -l | grep nginx
```

### Семейство Red Hat / CentOS / Rocky Linux / AlmaLinux (`dnf` / `rpm`):
```bash
# 1. Установка пакета (dnf - современная замена старому yum)
sudo dnf install -y nginx

# 2. Поиск пакета в репозиториях
sudo dnf search prometheus

# 3. Низкоуровневая утилита rpm:
rpm -qa | grep nginx          # Показать все установленные пакеты с nginx
rpm -ql nginx                 # Показать список всех файлов, которые установил пакет
```

## ⏰ 4. Синхронизация времени (NTP / Chrony / `timedatectl`)

> 🚨 **Почему это критично:**
> 1. Если на сервере сбилось время — **SSL-сертификаты перестанут считаться валидными** (ошибка «Сертификат еще не действителен или уже просрочен»).
> 2. **Prometheus откажется принимать метрики** с временным сдвигом (Time Drift) более 5 минут.
> 3. В распределенных логах (Loki / Elasticsearch) невозможно будет выстроить события в правильном хронологическом порядке.

```bash
# 1. Просмотр текущего времени, часового пояса и статуса NTP:
timedatectl

# Пример корректного вывода:
#                Local time: Sun 2026-08-16 21:00:00 MSK
#            Universal time: Sun 2026-08-16 18:00:00 UTC
#                  RTC time: Sun 2026-08-16 18:00:00
#                 Time zone: Europe/Moscow (MSK, +0300)
# System clock synchronized: yes    <--- ДОЛЖНО БЫТЬ YES!
#               NTP service: active <--- ДОЛЖНО БЫТЬ ACTIVE!

# 2. Установка часового пояса:
sudo timedatectl set-timezone Europe/Moscow
sudo timedatectl set-timezone UTC # На продакшене рекомендуется везде держать UTC!

# 3. Принудительное включение синхронизации времени по сети:
sudo timedatectl set-ntp on
```

## 🔑 5. Управление SSH-ключами и безопасность доступа

Парольный доступ по SSH на боевых серверах отключают в первый же день настройки (`PasswordAuthentication no`). Вход осуществляется исключительно по **криптографическим ключам**.

### Шаг 1. Генерация пары ключей на локальном компьютере:
```bash
# Рекомендуемый современный алгоритм Ed25519 (быстрее и надежнее старого RSA):
ssh-keygen -t ed25519 -C "admin@company.com"
```
* Будут созданы 2 файла в папке `~/.ssh/`:
  * `id_ed25519` — **Приватный (закрытый) ключ**. Никому не передавать!
  * `id_ed25519.pub` — **Публичный (открытый) ключ**. Копируется на удаленные серверы.

### Шаг 2. Копирование публичного ключа на сервер:
```bash
# Автоматическое добавление в authorized_keys сервера:
ssh-copy-id user@192.168.1.50

# Если утилиты нет, можно вручную дописать содержимое .pub файла в конец:
# ~/.ssh/authorized_keys на удаленном сервере
```

### Шаг 3. Строгие права доступа (Security Permissions):
Если выставить неправильные права, SSH-демон из соображений безопасности **откажется пускать вас по ключу**:

```bash
# 1. Права на саму папку .ssh:
chmod 700 ~/.ssh                  # rwx------ (только владелец может заходить в папку)

# 2. Права на файл с разрешенными ключами:
chmod 600 ~/.ssh/authorized_keys  # rw------- (только владелец может читать и писать)

# 3. Права на ваш приватный ключ:
chmod 600 ~/.ssh/id_ed25519       # rw-------
```
