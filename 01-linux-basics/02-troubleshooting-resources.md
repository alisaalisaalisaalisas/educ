# 📊 Модуль 1.2: Диагностика ресурсов: CPU, RAM, Disk, Load Average

Когда срабатывает алерт «High CPU», «Host Out of Memory» или «Disk Space Low», инженер должен быстро локализовать причину.

---

## 1. Load Average (LA) и CPU

### Понимание Load Average
Команда `uptime` или `w` показывает 3 числа:
```bash
$ uptime
 21:00:00 up 10 days, 2 users, load average: 2.15, 1.80, 0.95
```
Эти 3 числа — среднее количество процессов в очереди на исполнение (R - running) и в ожидании диска (D - uninterruptible sleep) за **1 минуту, 5 минут и 15 минут**.

* **Правило:** Сравнивай LA с количеством ядер процессора (`nproc` или `lscpu`).
  * Если ядер 4, а LA = 2.0 → система загружена на 50%.
  * Если ядер 4, а LA = 4.0 → система загружена на 100%.
  * Если ядер 4, а LA = 12.0 → огромная очередь задач, сервер «лагает».

### Утилиты анализа CPU
```bash
# Интерактивный монитор процессов
top
htop  # более удобный аналог

# Быстрый поиск топ процессов по CPU
ps aux --sort=-%cpu | head -n 10
```

## 2. Оперативная память и OOM Killer

### Анализ памяти (`free -m` / `free -h`)
```bash
$ free -m
              total        used        free      shared  buff/cache   available
Mem:          16000        6200        2100         400        7700        9400
Swap:          4000         120        3880
```
* **Важно:** В Linux свободная память отдается под `buff/cache` (дисковый кэш) — это нормально!
* Смотреть нужно на колонку **`available`** (доступная память, которую ОС может быстро отдать приложениям).

### OOM Killer (Out of Memory Killer)
Когда физическая память и swap заканчиваются, ядро Linux принудительно убивает самый «прожорливый» процесс.
```bash
# Как проверить, срабатывал ли OOM Killer:
dmesg -T | grep -i oom
journalctl -k | grep -i "killed process"
```

## 3. Дисковое пространство и Inodes (Иноды)

### Место на диске
```bash
# Общий статус всех смонтированных разделов
df -h

# Поиск самых тяжелых директорий в корне
du -sh /* 2>/dev/null | sort -hr | head -n 10

# Найти топ-10 самых больших файлов
find /var -type f -exec du -Sh {} + | sort -rh | head -n 10
```

### Заполнение Inodes (Файловых дескрипторов)
> ⚠️ **Частая ловушка на собеседовании:** «Место на диске есть (`df -h` показывает 40%), но создать файл нельзя (No space left on device). В чем причина?»
>
> **Ответ:** Закончились **inodes** (индексные дескрипторы) из-за огромного количества мелких файлов (например, сессии PHP, мелкие логи или письма в почтовой очереди).

```bash
# Проверка количества свободных inodes
df -i
```

## 4. Дисковый ввод-вывод (I/O Bottleneck)

Иногда CPU не загружен вычислениями, но процессор ждет ответа от медленного диска (`%iowait` в `top`).
```bash
# Мониторинг I/O активности по дискам (утилита sysstat)
iostat -xz 1 5

# Мониторинг процессов, нагружающих диск
iotop -o
```

---

## 📋 Чек-лист «Первые 60 секунд на упавшем сервере»
1. `uptime` — смотрим Load Average.
2. `free -m` — проверяем свободную память.
3. `df -h` и `df -i` — проверяем место и inodes на дисках.
4. `top` / `htop` — смотрим, кто жрет CPU / RAM и есть ли высокий `%wa` (iowait).
5. `dmesg -T | tail -n 50` — проверяем ошибки ядра и OOM Killer.
